# BurnerEye Prediction Report

Отдельное настольное GUI-приложение для проверки эксперимента BurnerEye и
формирования PDF-отчёта с расчётами MAE/MAPE, анализом динамики качества,
распределением ошибок и выбором лучших/худших кадров.

## Возможности

- проверяет `results.csv`, обязательные поля, числовые данные, единицы,
  уникальность `frame_id`, папку `frames` и temporal-окна;
- объединяет физически одинаковые режимы после пересчёта `kg/h`, `g/h` и
  `g/s` в базовую единицу `g/h`;
- обнаруживает конфликтующие значения `trained_regime` и блокирует отчёт до
  ручного выбора;
- не изменяет исходные `results.csv` и изображения;
- рассчитывает только MAE и MAPE как итоговые метрики;
- анализирует весь эксперимент, обученные/необученные режимы, каждый режим,
  а также начало, середину и конец;
- сравнивает результаты двух моделей на отдельной вкладке, учитывая только
  общие физические режимы и общие предсказываемые каналы;
- строит сравнительные графики «факт / модель 1 / модель 2» и отдельные
  сводные графики MAE/MAPE;
- формирует векторные графики прямо в PDF;
- сохраняет девять расчётных CSV и `processing.log`;
- проверяет сформированный PDF повторным открытием.

## Запуск готового EXE

Запустите:

```powershell
.\run.bat
```

Батник автоматически:

1. проверит наличие `dist\BurnerEyeReport.exe`;
2. сравнит дату EXE с исходниками и файлами зависимостей;
3. через `update_exe.bat` вызовет `build_exe.bat`, если EXE отсутствует или устарел;
4. запустит актуальный `BurnerEyeReport.exe`.

При первой сборке `build_exe.bat` создаёт `.venv`, если её ещё нет, устанавливает
зависимости из `requirements-build.txt` и формирует однофайловое Windows-приложение:

```text
dist\BurnerEyeReport.exe
```

Для ручной пересборки:

```powershell
.\build_exe.bat
```

Для проверки и обновления EXE без запуска приложения:

```powershell
.\update_exe.bat
```

Для сборки и автоматического обновления требуется Python 3.10 или новее.
На компьютере, где запускается уже актуальный EXE, Python не требуется.

## Запуск из исходников

Требуется Python 3.10 или новее.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\run_python.bat
```

Или:

```powershell
.\.venv\Scripts\python.exe main.py
```

В окне приложения выберите папку эксперимента, содержащую `results.csv` и
`frames`. Если указана родительская папка с единственным экспериментом на
ограниченной глубине до двух каталогов, приложение выберет его. Если найдено
несколько кандидатов, приложение перечислит их пути и попросит выбрать один.
Каталоги созданных отчётов при поиске исключаются.
Конфликтные режимы подсвечиваются. Выберите строки таблицы и назначьте им
итоговый статус, затем нажмите «Сформировать PDF-отчёт».

После проверки показываются отдельные количества прогнозов топлива и пара.
Пустая ячейка `predicted_fuel_flow` или `predicted_diluent_flow` означает, что
этот канал для строки не предсказывался. Ноль остаётся обычным числовым
прогнозом. Имя папки и `regime` не определяют канал. Оба фактических расхода
по-прежнему обязательны. Необязательные `video_index.csv` и `source.json`
добавляют метаданные к PDF и журналу; их отсутствие или повреждение не мешает
расчётам по `results.csv`. Частично завершённые видео отмечаются в
предупреждениях, а уже сохранённые записи учитываются.

Для сравнения откройте вкладку «Сравнение моделей», выберите две папки с
`results.csv` и нажмите «Проверить и сравнить». Совпадение режимов определяется
по фактическим расходам топлива и пара после приведения к `г/ч`, поэтому
внутренние номера `R001`, `R002` в двух папках могут различаться. Папки
`frames` для сравнительного отчёта не обязательны. У обеих моделей должен
найтись общий прогнозируемый канал хотя бы в одном общем режиме. Например,
топливный набор нельзя сравнить с паровым, даже если фактические режимы
совпадают. В GUI показывается отсутствие сопоставимых данных; такой отчёт не
создаётся.

## Результат

Внутри выбранного эксперимента создаётся папка:

```text
prediction_report_YYYY-MM-DD_HH-MM-SS/
├── prediction_report.pdf
├── csv/
│   ├── overall_metrics.csv
│   ├── trained_untrained_metrics.csv
│   ├── metrics_by_regime.csv
│   ├── metrics_by_regime_stage.csv
│   ├── overall_stage_metrics.csv
│   ├── prediction_timeline.csv
│   ├── error_distribution.csv
│   ├── selected_frames.csv
│   └── regime_classification.csv
└── processing.log
```

CSV записываются в UTF-8 с BOM, чтобы русские подписи корректно открывались
в Excel. MAE и значения расходов в отчёте приводятся к `г/ч`; исходная
единица каждой строки сохраняется в `prediction_timeline.csv`.
CSV метрик содержат отдельные `mae_fuel_record_count` и
`mae_steam_record_count`. В `prediction_timeline.csv` и `selected_frames.csv`
добавлены признаки доступности прогнозов и причины исключения MAPE:
`prediction_missing` или `expected_zero`. Пустое значение причины означает,
что строка вошла в MAPE. Эти файлы также сохраняют имя исходного видео,
интервал окна и исходные индексы кадров. `timestamp` — время обработки, а не
время в исходном видео.

Сравнительный отчёт сохраняется внутри папки первой модели:

```text
model_comparison_YYYY-MM-DD_HH-MM-SS/
├── model_comparison_report.pdf
├── csv/
│   ├── overall_model_comparison.csv
│   ├── metrics_by_common_regime.csv
│   ├── prediction_timeline_comparison.csv
│   └── excluded_regimes.csv
└── processing.log
```

`excluded_regimes.csv` перечисляет режимы, которые были исключены из
сравнения, поскольку присутствуют только у одной из моделей.

## Особые случаи

- Нулевое фактическое значение участвует в MAE, но не в MAPE.
- Пустой прогноз не превращается в ноль и не включается в метрики своего
  канала. Отсутствующий канал отображается как «Нет прогнозов»; его счётчик
  MAE равен нулю.
- Если MAPE-подобная оценка кадра невозможна, рейтинг использует
  нормализованную абсолютную ошибку; это отмечается в CSV и журнале.
- Отдельные отсутствующие кадры не исключают строки из расчётов.
- Для PDF нужен хотя бы один читаемый основной кадр `frames/<frame_id>.jpg`.
- При наличии менее четырёх кадров в отчёт входят все доступные без повторов.
