# Краткая инструкция пользователя BurnerEye Prediction Report

Приложение проверяет результаты предсказаний BurnerEye, рассчитывает метрики
качества и формирует PDF-отчёт с таблицами, графиками и расчётными CSV.

## Что требуется на входе

Для отчёта по одной модели подготовьте папку эксперимента:

```text
папка_эксперимента/
├── results.csv
├── video_index.csv  # необязательно: метаданные временных окон
├── source.json      # необязательно: происхождение и статус видео
└── frames/
    ├── <frame_id>.jpg
    └── <frame_id>/...  # необязательные кадры temporal-окна
```

В `frames` должен находиться хотя бы один читаемый основной файл
`<frame_id>.jpg` или `<frame_id>.jpeg`. Имя файла без расширения должно
совпадать со значением `frame_id` в CSV. Отсутствующий отдельный кадр не
исключает строку из расчёта метрик, но такая строка не участвует в выборе
лучших и худших кадров.

`results.csv` должен быть записан в UTF-8. Поддерживаются разделители `,`, `;`
и табуляция.

### Столбцы `results.csv`

| Столбец | Содержание |
|---|---|
| `timestamp` | Время обработки строки |
| `frame_id` | Уникальный идентификатор кадра |
| `unit` | Единица расходов: `kg/h`, `g/h` или `g/s` |
| `expected_fuel_flow` | Фактический расход топлива |
| `expected_diluent_flow` | Фактический расход пара |
| `trained_regime` | `1` — режим был в обучении, `0` — не был |
| `predicted_fuel_flow` | Предсказанный расход топлива; ячейка может быть пустой |
| `predicted_diluent_flow` | Предсказанный расход пара; ячейка может быть пустой |
| `regime` | Предсказанная моделью метка режима |
| `regime_confidence` | Уверенность модели от 0 до 1; значение может быть пустым |

Все перечисленные столбцы должны присутствовать. Значения обоих фактических
расходов, `timestamp`, `frame_id`, `unit` и `trained_regime` обязательны.
Пустой прогноз означает отсутствие предсказания этого канала для строки;
числовой ноль остаётся настоящим прогнозом. Если оба прогноза пусты, строка
исключается. Некорректное непустое значение любого прогноза также исключает
строку, даже если второй канал заполнен. Канал определяется доступностью
прогнозов, не именем папки или модельной меткой `regime`.

Перед расчётами все расходы приводятся к `г/ч`. Физический режим определяется
парой фактических расходов топлива и пара, поэтому одинаковые режимы,
записанные в разных единицах, объединяются.

`video_index.csv` и `source.json` необязательны и не влияют на расчётные цели.
Некорректные дополнительные файлы дают предупреждения; значения из
`source.json` никогда не подменяют содержимое `results.csv`. Связь видео
выполняется по `frame_id`. Имя видео, интервал окна, исходные индексы кадров и
статус частичного завершения могут попасть в отчёт. `source_video` и
`model_path` хранятся как текстовые метаданные; приложение не открывает эти
пути. Ошибка чтения исходного видео после сохранения части записей не отменяет
уже сохранённые результаты.

Для сравнения моделей нужны две папки с корректными `results.csv`. Папки
`frames` в этом режиме необязательны. Сравнение строится только по общим
физическим режимам и тем каналам, которые предсказывают обе модели в одном и
том же общем режиме. Если общие фактические режимы есть, но ни одного общего
прогнозируемого канала нет, приложение сообщает об этом и отчёт не создаёт.

## Как получить результат

### Отчёт по одной модели

1. Откройте вкладку **«Отчёт по одной модели»**.
2. Выберите конкретную папку эксперимента или укажите путь и нажмите
   **«Проверить путь»**. Можно выбрать родительскую папку, если внутри на
   глубине до двух каталогов найден ровно один `results.csv`. Если найдено
   несколько экспериментов, приложение перечислит полные пути; выберите один
   из них вручную. Отчётные папки при поиске не учитываются. Наборы никогда не
   объединяются автоматически.
3. Просмотрите вкладку **«Ошибки и предупреждения»**.
4. Если режим одновременно отмечен как обученный и необученный, выберите его
   в таблице и назначьте итоговый статус.
5. При необходимости измените порог существенного изменения качества.
   Значение по умолчанию — 5%.
6. Нажмите **«Сформировать PDF-отчёт»**.
7. После завершения нажмите **«Открыть папку отчёта»**.

### Сравнение двух моделей

1. Откройте вкладку **«Сравнение моделей»**.
2. Выберите папки первой и второй моделей.
3. Нажмите **«Проверить и сравнить»**.
4. Проверьте список общих и исключённых режимов.
5. Нажмите **«Сформировать сравнительный PDF»**.

В сравнении участвуют только физические режимы, присутствующие у обеих
моделей. Для каждого режима GUI показывает доступные метрики топлива и пара,
а также итог только там, где канал сопоставим у обеих моделей. Внутренние
имена режимов и количество строк у моделей могут различаться. Например,
топливная модель и модель прогноза пара не сравнимы между собой; GUI покажет
понятное сообщение вместо сравнительного отчёта.

## Что получается на выходе

Исходные CSV и изображения приложение не изменяет.

### Отчёт по одной модели

Результат создаётся внутри выбранной папки эксперимента:

```text
prediction_report_YYYY-MM-DD_HH-MM-SS/
├── prediction_report.pdf
├── csv/
│   ├── overall_metrics.csv
│   ├── trained_untrained_metrics.csv
│   ├── metrics_by_regime.csv
│   ├── metrics_by_regime_stage.csv
│   ├── overall_stage_metrics.csv
│   ├── prediction_timeline.csv
│   ├── error_distribution.csv
│   ├── selected_frames.csv
│   └── regime_classification.csv
└── processing.log
```

- `prediction_report.pdf` — итоговые метрики, графики, анализ динамики,
  обученные и необученные режимы, лучшие и худшие кадры.
- `overall_metrics.csv` — метрики всего эксперимента.
- `trained_untrained_metrics.csv` — метрики обученных и необученных режимов.
- `metrics_by_regime.csv` — метрики каждого физического режима.
- `metrics_by_regime_stage.csv` — метрики начала, середины и конца каждого
  режима.
- `overall_stage_metrics.csv` — метрики этапов всего эксперимента и групп
  режимов.
- `prediction_timeline.csv` — фактические значения, предсказания и ошибки
  каждой строки, доступность каналов, причину исключения MAPE и доступные
  метаданные видео. Поле `timestamp` означает время обработки.
- `error_distribution.csv` — знаковые ошибки топлива и пара.
- `selected_frames.csv` — лучшие и худшие кадры с методом ранжирования.
- `regime_classification.csv` — исходные и итоговые статусы режимов.
- `processing.log` — журнал проверки и формирования отчёта.

### Сравнение моделей

Результат создаётся внутри папки первой модели:

```text
model_comparison_YYYY-MM-DD_HH-MM-SS/
├── model_comparison_report.pdf
├── csv/
│   ├── overall_model_comparison.csv
│   ├── metrics_by_common_regime.csv
│   ├── prediction_timeline_comparison.csv
│   └── excluded_regimes.csv
└── processing.log
```

`excluded_regimes.csv` содержит режимы, которые исключены из расчётов,
поскольку присутствуют только у одной модели.

Все расчётные CSV записываются в UTF-8 с BOM для корректного открытия русских
подписей в Excel.
В таблицах метрик `record_count` — число строк области анализа;
`mae_fuel_record_count` и `mae_steam_record_count` — число прогнозов каждого
канала, вошедших в MAE. Счётчики `mape_*_record_count` исключают нулевой факт.
В timeline и `selected_frames.csv` `*_prediction_available` равен `0` для
пустого канала. `*_mape_exclusion_reason` содержит `prediction_missing` или
`expected_zero`, либо остаётся пустым, если строка вошла в MAPE.

## Описание метрик

Метрики рассчитываются отдельно для топлива и пара. В формулах:

- `факт` — значение `expected_...`;
- `модель` — значение `predicted_...`.

Расходы, MAE и ошибки выражаются в `г/ч`. APE и MAPE выражаются в процентах.
Чем меньше MAE, APE, MAPE и оценка кадра, тем точнее результат.

### Абсолютная ошибка

```text
Абсолютная ошибка = |модель − факт|
```

Показывает величину ошибки отдельной строки без учёта направления.

### Знаковая ошибка

```text
Знаковая ошибка = модель − факт
```

Положительное значение означает завышение, отрицательное — занижение.
Приложение сообщает о преобладающем направлении ошибки, если не менее 60%
ненулевых ошибок имеют одинаковый знак.

### APE — абсолютная процентная ошибка

```text
APE = |модель − факт| / |факт| × 100%
```

Рассчитывается для отдельной строки только при ненулевом фактическом расходе.

### MAE — средняя абсолютная ошибка

```text
MAE = среднее значение абсолютных ошибок
```

Показывает среднюю величину ошибки группы строк в `г/ч`. Строки с нулевым
фактическим расходом участвуют в MAE.

### MAPE — средняя абсолютная процентная ошибка

```text
MAPE = среднее значение APE
```

Рассчитывается только по строкам с ненулевым фактическим расходом. Нулевой
факт исключается из соответствующего MAPE, но остаётся в MAE.

### Количество записей

- `record_count` — количество строк в области анализа; при частичном покрытии
  оно может отличаться от числа прогнозов конкретного канала.
- `mae_*_record_count` — число строк с прогнозом канала, вошедших в MAE.
- `mape_*_record_count` — количество строк с ненулевым фактом, вошедших в
  MAPE топлива или пара.

Количество записей MAPE может быть меньше `record_count`.

### Оценка кадра

`frame_error_score` используется для выбора лучших и худших кадров:

1. рассчитывается APE каждого доступного в строке канала;
2. итоговая оценка — среднее только доступных ошибок каналов;
3. если прогноз есть, но фактическое значение равно нулю, вместо APE
   используется абсолютная ошибка этого прогноза, нормированная на медиану
   ненулевых фактических расходов того же канала.

Кадры с меньшей оценкой считаются лучшими.

### Показатель этапа и порог существенного изменения

Записи по времени делятся на три максимально равные части: **«Начало»**,
**«Середина»** и **«Конец»**.

Показатель этапа использует только каналы с прогнозами во всех трёх участках.
Для каждого канала MAPE применяется, когда он определён во всех участках;
иначе во всех участках используется MAE. Каналы с разными типами показателя
получают отдельные выводы. Если общего канала на всех участках нет, приложение
сообщает о недостатке сопоставимых данных. Порог сравнивает худшее и лучшее
значения относительно лучшего.

Порог влияет только на текстовый вывод о динамике качества и не изменяет
рассчитанные MAE или MAPE.

### `regime_confidence`

Это входная уверенность модели в классификации режима. Приложение проверяет
ожидаемый диапазон от 0 до 1, но не использует `regime_confidence` при расчёте
MAE, MAPE, ранжировании кадров или выборе лучшей модели.

### Выбор лучшей модели

В сравнительном отчёте модель оценивается только по общей прогнозируемой
величине в общем физическом режиме. Если метрика отсутствует хотя бы у одной
модели, выводится **«Нет сопоставимых данных»**. Практически равные числовые
значения отмечаются как **«Одинаково»**. Если MAPE нельзя рассчитать из-за
нулевого факта, сравнение по MAE остаётся доступным.
