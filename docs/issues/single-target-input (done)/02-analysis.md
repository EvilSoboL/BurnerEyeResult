# 02. Рассчитывать ошибки по доступным прогнозам

Приоритет P1. Зависимость: 01. Labels: enhancement, input-format.

## Работа

Точки изменения: `models.MetricSet.as_dict`, `analysis.calculate_metrics`, `_row_metrics`, `_select_frames`, `_quality_conclusion`, `_direction_conclusion`, `analyze_experiment`. Начать с расчётов и тестов, затем выбор кадров и выводы.

- MAE считать отдельно по каждому каналу с прогнозом. Добавить счётчики MAE, например `mae_fuel_count`, `mae_steam_count`, и экспортные ключи `mae_fuel_record_count`, `mae_steam_record_count`. Новые поля не должны ломать старые вызовы конструктора MetricSet.
- MAPE исключает отсутствие прогноза и нулевой факт. `record_count` остаётся числом записей, а не максимумом/суммой счётчиков каналов.
- Signed/absolute/percentage ошибка отсутствующего прогноза — None. Сохранить нулевую настоящую ошибку.
- Рейтинг кадра — среднее оценок доступных каналов. Описывать каналы в score_method; не вызывать float(None). Сохранить четыре разных кадра и fallback при нулевом факте. Для смешанного покрытия добавить processing_note о разных составах оценки.
- Вывод о динамике использует сопоставимые каналы и типы метрик во всех трёх стадиях по правилу 6 FORMAT.md. Направление ошибки без прогнозов явно недоступно.

## Проверки и приёмка

- [x] Ручной пример: две строки с фактами fuel=100, steam=50; первая прогнозирует fuel=110, вторая steam=45. record_count=2, MAE fuel=10/steam=5, MAPE fuel=10%/steam=10%, четыре счётчика=1.
- [x] Канал полностью пуст: MAE/MAPE=None, счётчики 0. Нулевой прогноз учитывается; нулевой факт учитывается в MAE и исключается из MAPE.
- [x] Все уровни агрегации (общий, trained/untrained, режим, стадии) используют те же правила.
- [x] Контрольные значения полных наборов совпадают с evidence.json с допуском 1e-9.
- [x] Выбор лучших/худших по одному каналу совпадает с ручным рейтингом; нет повторов ID и фиктивных ошибок второго канала.
- [x] Стадии с разными каналами и нулевыми фактами не дают ложных выводов из несопоставимых оценок.
- [x] Старые двухканальные тесты проходят.

## Выполнение этапа 2

- Изменены `burner_eye_report/models.py`, `burner_eye_report/analysis.py` и `tests/test_analysis.py`.
- `MetricSet` получил счётчики MAE с defaults для совместимости конструкторов; `as_dict()` экспортирует `mae_fuel_record_count` и `mae_steam_record_count`. MAE и MAPE считают только доступные прогнозы своего канала, при этом `record_count` остаётся числом строк.

- Вывод по динамике использует только каналы с покрытием на всех трёх стадиях. Для каждого канала MAPE используется только если он определён во всех стадиях, иначе MAE используется во всех стадиях; при разных типах метрик выводы по каналам остаются отдельными.
