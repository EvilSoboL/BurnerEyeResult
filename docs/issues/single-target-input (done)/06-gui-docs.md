# 06. Показать тип прогноза и объяснить выбор папки

Приоритет P2. Зависимости: 01–05. Labels: enhancement, input-format.

## Работа

Точки изменения: `gui.py` (`_load`/worker-функции, summary, состояние кнопок и вкладка сравнения; точные имена найти по вызовам load_experiment), `README.md`, `USER_GUIDE.md`.

- После загрузки показать цель и счётчики доступных прогнозов, в том числе смешанный вход. Для новых наборов отсутствие второго канала не должно выглядеть как повреждение всех строк.
- Сохранить ручную классификацию trained_regime и существующую блокировку при конфликте/ошибках основных данных. Предупреждение о частичном source.json не отключает генерацию.
- Для выбора `Расход пара`/`Расход топлива` можно реализовать явное разрешение единственной вложенной папки с results.csv. Если это реализуется, вынести определение кандидатов в отдельную тестируемую функцию; искать только понятную ограниченную глубину, исключать каталоги с отчётами.
- При выборе общего корня с двумя экспериментами показать конкретные кандидаты и необходимость выбрать один. Не объединять и не брать первый по сортировке. Минимально допустим понятный отказ с путями; автоматический выбор родителя не является обязательной функцией.
- Сообщение сравнения разноканальных моделей выводить в обычном GUI-потоке обработки ошибок, без traceback пользователю. Worker не должен напрямую изменять Tk widgets.
- В руководстве описать структуру папок, пустой прогноз, единицы, необязательные метаданные, частичные видео и сравнение. Уточнить, что имя папки не определяет канал, timestamp — время обработки, а для одиночного PDF нужны frames.
