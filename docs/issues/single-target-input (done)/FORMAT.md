## Причина несовместимости

`loader._parse_row` вызывает `_parse_finite` для обоих прогнозов; пустой прогноз вызывает ValueError. В итоге исключаются все строки. Пустые regime и regime_confidence уже допустимы. Схема JPEG уже поддерживается. Дополнительные CSV/JSON сейчас не читаются.

Изменение только загрузчика недостаточно: `analysis.calculate_metrics`, `_row_metrics` и `_select_frames` выполняют арифметику с обоими прогнозами; `SelectedFrame.abs_error_*` требуют float. В `reporting` есть приведение отсутствующих ошибок через `or 0.0`; оно исказит гистограммы. `comparison.metric_winner` сейчас считает единственную доступную метрику победителем — для этих экспериментов это ложный вывод. Chart flowables уже частично поддерживают None; проверить вызывающие функции и легенды.

## Решения для реализации

1. Сохраняем десять обязательных **колонок**. Ослабляем только требование заполненности прогнозов. Обе фактические величины, timestamp, frame_id, unit и trained_regime остаются обязательными.
2. Пустая или пробельная ячейка прогноза → `None` в исходном и нормализованном поле. Ноль → настоящий прогноз 0. Непустые нечисловые, NaN/Inf → исключение строки с предупреждением, даже если другой прогноз корректен. Обе ячейки пусты → исключение строки. Тот же принцип применяется к старым файлам с частично отсутствующими прогнозами.
3. Количество строк эксперимента — число принятых записей. MAE топлива и пара имеют отдельные счётчики валидных прогнозов; MAPE — свои счётчики с исключением нулевого факта. Нет прогнозов канала → метрики None, счётчики 0. `MetricSet.record_count` не становится количеством прогнозов одного канала.
4. Группировка по паре фактических расходов и статусы trained_regime не меняются. Цель определяется из наличия прогнозов, а не имени папки, regime или имени модели. Для смешанных строк показываем покрытие каждого канала; агрегированные расчёты допускают разные подмножества, что обозначается в отчёте.
5. Лучшие/худшие кадры ранжируются по доступным каналам строки. При нулевом факте сохраняется существующий fallback через нормализованную абсолютную ошибку только доступного прогноза. Метод и набор каналов записываются явно. Для смешанных строк отмечается различие состава оценки.
6. Стадии сохраняют текущий split_three по timestamp. Сравнивать качество стадий следует по одинаковому непустому набору каналов, доступных во всех трёх стадиях. Если такого набора нет, сообщить недостаточность сопоставимых данных. Если MAPE данного канала недоступен хотя бы в одной стадии, использовать его MAE во всех стадиях; не смешивать MAE и MAPE в одной усреднённой оценке. При двух каналах с разными доступными типами метрик давать выводы по каналам отдельно. Полный старый вход с ненулевыми фактами сохраняет прежний результат.
7. Нет ошибок канала → «Нет прогнозов»; есть прогнозы, но факт всегда 0 → «MAPE не определён: нулевой факт». Не выводить «ошибка 0» или «направления ошибки нет» для канала без прогнозов. CSV-значение None → пустая ячейка, не 0/NaN/строка None. Добавить счётчики MAE и причины исключения MAPE без удаления старых колонок.
8. Сравнение работает по общим физическим режимам и общим предсказываемым каналам. Для отсутствующей метрики у любой стороны победитель «Нет сопоставимых данных». Если в общих режимах нет ни одного канала с прогнозами у обеих моделей, analyze_comparison выдаёт понятный ValueError. Два новых набора как раз такой случай. Автоматическое склеивание не требуется.
9. source.json и video_index.csv необязательны. Ошибка чтения/схемы или несогласованность → предупреждение; корректные results остаются доступны. Никаких открытий путей source_video/model_path. Сохранять исходный status=error и stop_reason как предупреждение о частичном результате.
10. Выбор конкретной папки с results.csv — обязательный минимум. Для удобства GUI может однозначно разрешать родителя с единственным экспериментом; при двух и более кандидатах должен просить выбрать конкретный эксперимент через список или выдавать понятную ошибку с путями. Загрузчик не сливает независимые данные и не выбирает первый найденный набор.
